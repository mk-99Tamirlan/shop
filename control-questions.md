# Контрольные вопросы
## Лаб 1
1. Образ содержит файлы и инструкции запуска, контейнер является его запущенным экземпляром. Именованный том pgdata сохраняется после down, а down -v удаляет том и данные.
2. Локальный процесс обращается к опубликованному порту компьютера. В сети Compose имя postgres разрешается во внутренний адрес контейнера.
3. Слой установки зависимостей повторно используется при изменении только исходного кода.
4. FOR UPDATE блокирует строку до окончания транзакции, исключая одновременное списание последней единицы товара.
5. p95 показывает время, быстрее которого или за которое завершились 95% запросов. Среднее может скрывать медленные запросы.
6. Определяется после запуска по максимальной загрузке CPU в docker stats. Пока замера нет.
## Лаб 2
1. Отношение RPS второй лабораторной к первой вычисляется после замеров. Рост не обязательно трёхкратный, поскольку база общая, а ресурсы ограничены. Узкое место определяется по docker stats.
2. least_conn направляет запрос менее занятому воркеру, что полезно при неодинаковой длительности операций.
3. Повтор уже отправленного POST может создать заказ дважды. Nginx по умолчанию не повторяет неидемпотентный запрос после его отправки upstream.
4. Корзина в памяти одного процесса недоступна другим воркерам и теряется при перезапуске. Её следует хранить в общей базе или Redis.
5. PostgreSQL и единственный балансировщик остаются точками отказа; также все контейнеры зависят от одного компьютера.
